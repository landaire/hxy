# M4d: GPUI IPC Single-Instance + CLI Open Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans.

**Goal:** GPUI app parity for single-instance behavior: a second launch (or Finder "Open With") forwards its file paths to the already-running window instead of starting a new process; CLI paths are canonicalized and filtered like the egui app.

**Architecture:** The egui IPC subsystem is framework-agnostic except two thin seams -- `ipc::start_server` returns an `egui_inbox::UiInbox`, and `macos_open` holds an `egui::Context` for repaint. Extract the framework-neutral cores (socket + rkyv wire protocol, CLI parsing, Apple-Event/NSServices handling) into a new desktop-only `hxy-ipc` crate that takes a generic delivery sink + wake callback; the egui app adapts via UiInbox, the gpui app adapts via a channel polled by the executor.

**Reference map (read first):** docs/superpowers/plans/2026-08-20-m4-plugins-ipc-settings-console-map.md section (2) IPC SINGLE-INSTANCE (cli.rs Cli/resolved_files; ipc.rs GenericNamespaced socket "hxy.sock", u32 LE len + rkyv IpcMessage::Open{paths: Vec<String>}, MAX_MESSAGE_BYTES 16MiB, try_send_to_running_instance, start_server, read_message with AlignedVec<16>; drain_external_open_requests; macos_open.rs Apple Events kAEOpenDocuments + NSServices, REPAINT_CTX, install() BEFORE window creation, drain_pending_paths, the crash rationale for install-before-run). Global Constraints = docs/superpowers/plans/2026-08-20-m4a-gpui-templates.md Global Constraints.

**Current gpui state:** main.rs does `std::env::args().skip(1).map(PathBuf::from)` -- no canonicalization, no single-instance, no macOS open-with. Workspace::new(initial: Vec<PathBuf>, ...) opens the initial set; the running-window open path is the disk-open flow used by open_or_focus.

### Task 1: hxy-ipc crate -- CLI + socket protocol (framework-neutral)

**Files:** create crates/hxy-ipc/{Cargo.toml, src/lib.rs, src/cli.rs, src/socket.rs}; modify crates/hxy/src/{cli.rs,ipc.rs} -> shims/adapters, crates/hxy/Cargo.toml, root manifests + BUCK.

- Move VERBATIM into hxy-ipc: cli.rs (Cli, parse_args, resolved_files -- pure clap, canonicalize-vs-CWD + drop-missing); ipc.rs core (SOCKET_NAME, MAX_MESSAGE_BYTES, IpcMessage {Open{paths: Vec<String>}} with rkyv derives, try_send_to_running_instance, read_message, the listener bind with reclaim_name/try_overwrite). Replace `start_server(ctx) -> UiInbox` with a neutral `start_server(on_open: impl Fn(Vec<PathBuf>) + Send + 'static) -> io::Result<()>` (spawns the listener thread calling on_open per message) OR `start_server() -> io::Result<Receiver<Vec<PathBuf>>>` returning a std mpsc receiver (pick the form that adapts cleanly to BOTH egui UiInbox and gpui executor -- the Receiver form is likely cleanest: egui polls it in update + request_repaint, gpui polls it via a Timer loop or Notify). Keep the rkyv wire format byte-identical (the two apps must interop on the same socket name only ONE app runs at a time, but the format must stay stable).
- egui adapters: crates/hxy/src/ipc.rs keeps a thin `start_server(ctx)` wrapping the core receiver + a UiInbox (or directly polls the receiver in the existing drain path); cli.rs re-exports. Behavior byte-identical; ipc.rs unit tests (roundtrip/oversize/garbage) move with the core.
- hxy-ipc deps: interprocess, rkyv, clap, thiserror. Desktop-only crate (interprocess); egui dep target-gated as today.

**Gate:** root tests/clippy/buck green; egui IPC behavior unchanged. Commits: `refactor(hxy): extract ipc protocol and cli into hxy-ipc`, `build: register hxy-ipc with reindeer` if BUCK changes.

### Task 2: hxy-ipc macOS open-with core (framework-neutral wake)

**Files:** crates/hxy-ipc/src/macos_open.rs (new, cfg macos), crates/hxy/src/macos_open.rs -> shim, Cargo.tomls (objc2 deps move/duplicate), BUCK.

- Move macos_open.rs core VERBATIM (Apple Events registration, NSServices provider, HxyMacOpenHandler define_class!, PENDING_PATHS, install(), drain_pending_paths, nsurl_to_pathbuf) but replace `REPAINT_CTX: OnceLock<egui::Context>` + repaint calls with a neutral wake: `set_wake(Arc<dyn Fn() + Send + Sync>)` stored in a OnceLock, called after push_paths. egui adapts: set_wake(move || ctx.request_repaint()). Keep install()-before-window contract intact (documented crash rationale).
- objc2/objc2-foundation/objc2-app-kit deps move to hxy-ipc (feature-gated macos).

**Gate:** root (macos) tests/clippy/buck green; egui macOS open-with unchanged (compile-verified; runtime needs Finder). Commit: `refactor(hxy): extract macos open-with into hxy-ipc`.

### Task 3: gpui single-instance + CLI + macOS open wiring

**Files:** gpui/hxy-gpui/src/main.rs, gpui/hxy-gpui/src/workspace.rs (external-open entry point), gpui/Cargo.toml + gpui/hxy-gpui/Cargo.toml (hxy-ipc dep), gpui/Cargo.lock.

- main.rs startup order (mirror egui main.rs): (1) i18n init (already there); (2) macos_open::install() BEFORE the gpui Application runs its window (macOS); (3) let files = hxy_ipc::resolved_files(); (4) if hxy_ipc::try_send_to_running_instance(&files).is_ok() { return } (forwarded to the running instance, exit without opening a window); (5) else start the app: start_server(...) obtains the open-request receiver; wire it + macos_open drain into the gpui executor -- a `cx.spawn` Timer-poll loop (or a background thread + gpui channel) that drains pending paths and calls a Workspace method to open them; macos_open::set_wake(...) triggers the same drain. Workspace initial set = files.
- Workspace external-open entry: `open_external_paths(paths: Vec<PathBuf>, window, cx)` reusing the disk-open path (open_or_focus per path; focus the window/bring-to-front if the gpui/platform API allows -- check gpui for window activate; if absent, note). Dedup: opening an already-open path focuses its tab (open_or_focus already does).
- i18n: any user-visible string (none expected; forwarding is silent). 

**Gate:** gpui tests/clippy/fmt green; root gates if root touched (it isn't beyond Tasks 1-2). Serial cargo.
**Test:** a #[gpui::test] cannot span processes; instead a unit/integration test of the receiver-drain -> open_external_paths path (feed a Vec<PathBuf> through the channel, assert tabs open); the true two-process behavior is covered by the milestone-gate shell test.
Commit: `feat(hxy-gpui): single-instance IPC, CLI open, and macOS open-with`.
